# Financial close and cash forecasting

Open **Money → Financial close** (`/financial_close`). Select an Eastern business date. This connects existing source reports, originals, controls, follow-ups and version-bound reviews into an operational close workflow. It uses local data and never sends email/messages, writes to a source provider, posts ledger transactions or moves money.

1. **Completeness:** inspect source-confirmed imports and coverage. Track every additional expected invoice, statement or processor report with a local owner/due date. Observed activity and tracked requests are not an exhaustive report inventory.
2. **Retention:** retain original bytes with source and coverage; use corrections rather than replacement. The library links covered originals to matching requests after explicit review/progress. Google Drive is pending; originals remain encrypted in Rupert without automatic deletion.
3. **Reconciliation:** check signed Rupert-minus-source differences by currency/location. Gateway observations, processor deposits and sales remain separate. Manually document bank funding, fees and timing using source evidence; the application does not infer payment-to-order or payout-to-bank links.
4. **Follow-up:** assign unresolved work, due dates and evidence. Record next steps in Rupert; no messages or automatic reminders are sent. Closing a package never closes requests.
5. **Review:** record Reviewed or Needs attention against the current daily report fingerprint. Later source/evidence changes require a new review.
6. **Close/report:** confirm the original, bank/exception and retention checklist and enter a closing explanation. Complete recorded checks requires a current Reviewed record and no observed comparison, coverage, import or open-follow-up issues. Otherwise choose documented exceptions. Policy-specific requirements, including any mandatory cloud copy, must be reviewed and documented by the operator. This is an evidence package, not legal compliance certification.
7. **Forecast:** open the cash scenario for the same baseline date. Enter one currency, an opening balance with its basis, optional minimum reserve, assumptions and explicit weekly bank receipts/payments. Enter 0 where no movement is planned; include payroll, taxes, fees and expenses once. Choose 4, 8 or 13 weeks. Calculate, download CSV or retain a version with its assumptions. Amounts use integer cents and no currency conversion. The first opening/weekly shortfall is highlighted; weekly balances do not model intraday funding delays. This is manual planning rather than an imported bank balance or an automatic settlement prediction.

The close action verifies included original checksums and atomically retains the current reconciliation CSV and a JSON close package with report fingerprint, review, original references/checksums, current follow-up versions/notes, issues, checklist, explanation and reviewer. Exact replays reuse the same artifacts. A changed source or follow-up fingerprint rejects a stale close form; inputs are preserved. Previous packages stay available and show when evidence/progress has changed.

`close_package` and `cash_forecast` are generated document kinds, stored through the existing encrypted, tenant-scoped evidence vault with no new migration. They appear in the library's report archives and cannot be uploaded as source originals or requested as missing source reports. They are excluded from daily source evidence fingerprints, preventing a retained close/scenario from invalidating its own source review. The existing optional Drive retention classifier treats them as reports but consent and sync remain pending.

Reading requires reports.read; retaining close/forecast versions additionally requires reports.write. Report readers may preview/download scenarios. Employee-only roles retain their fixed self-service boundary. Entire close/forecast form containers are filtered from request logs; responses use no-store/nosniff and writes use CSRF protection. Scenario amounts are POST fields rather than URL parameters. Originals, packages, scenarios and encrypted history remain in consistent database/configuration backups; saved Rails encryption keys are required for restoration.

Daily reconciliation CSV and daily/weekly/monthly source summaries remain available from the close workspace. Source summaries preserve separate currencies and evidence layers; they are not substituted for bank reconciliation or a complete accounting P&L.

The close workspace puts actionable blockers first: missing source/currency/location controls, comparison/coverage/import checks, open follow-ups and missing/stale/Needs attention review. Current review is explicitly required for any package; other unresolved checks block a complete close while allowing an explained exception package. Missing-report actions preserve exact scope and reuse an existing open request. The first overdue follow-ups expose next steps and progress actions. Reference stages remain in an expandable workflow section.

Cash shortfall results show the amount below the entered reserve (or zero), with a direct jump to opening cash or the affected week. Editing any assumption marks the displayed calculation as stale and disables CSV/retention until recalculation. Server-side amount, scope and baseline checks remain authoritative.

Across days now shows each date's close-check count, current/missing/stale review, latest retained package and whether evidence or follow-up progress changed since that package. Each date links to financial close, a cash plan with that baseline, and its overdue queue. A request covering several dates appears on each covered date; counts must not be added into a distinct-request total. Missing reviews are shown separately from the overview's report/follow-up issue count, and no quiet date is certified complete. Previous/next-day links support sequential close review.

The forecast baseline panel links to close evidence, comparison across dates and overdue work. Changing the entered close date hides the previous baseline status and asks for calculation to refresh it, while preserving entered cash assumptions. Open close checks do not prevent manual scenario planning or replace the reviewer’s close decision.

Use the date-focus shortcuts to show overdue work, missing register reports, missing/stale reviews or changed close packages within the selected seven dates. Focus counts describe dates, not distinct requests; the global priority queue remains across all dates. The next action on each date and forecast baseline goes directly to the earliest overdue follow-up with its owner and latest note, or to the leading close check when no overdue work remains. These are navigation shortcuts: they do not change progress, send reminders or certify a close.

These shortcuts retain the existing report-reader/writer and employee access boundaries.

Missing-report requests opened from close checks, cash baselines or date cards keep the selected covered close date through creation, duplicate replay, original upload and progress saving. Upload errors retain that return context. Only an ISO business date within the request's coverage is accepted. The upload panel names the request and offers a direct return to progress; adding a file still requires an explicit evidence review and save.

On the progress form, **Keep investigating**, **Waiting on report** and **Resolve follow-up** select the corresponding status and focus the note without saving. The next-step guidance explains the owner/date or closing reason needed, and switching decisions preserves entered text. The normal status selector remains available. A reviewer can document an exception without evidence; resolving a request never certifies reconciliation or financial close. No action sends email or messages.

Searching retained originals from a follow-up, close priority card or cash baseline keeps the request and selected covered close date. The library shows the request's owner, due date, full coverage and matching-original count for the current page. Filter submissions, pagination, clearing filters and expired page recovery retain this context. Exact request matches offer **Review & use for this request**; partial coverage or a different source, kind or register scope cannot be selected. Evidence selection still requires an explicit progress note and save.

An empty request search offers a return to that request instead of creating a duplicate. **Reset to requested scope** clears search terms and restores the requested source/period. Other across-date follow-up shortcuts remain available in a collapsed section. Searches opened from a close date before a request exists retain a validated return to close and carry that date into subsequent request tracking. Readers can inspect scope and originals, while evidence-link and upload actions remain writer-only.

The [request-search deployment receipt](financial-close-request-search-deployment-2026-10-16.md) records the release, monthly-period handoff checks and preserved access data.

Overdue progress forms preview the next overdue request across all dates, including its due age, owner, covered period and linked-original state. **Save and work next overdue** saves only the current request and selects the earliest-due remaining item from the latest workspace queue, excluding the saved request. A changed or resolved preview target is not forced open. The selected close date carries forward only if the next request covers it. Blank notes, invalid changes and stale versions stay on the current form with entered text preserved.

If there is no other overdue request, **Save and check overdue queue** returns to the queue after saving. This does not imply that the current request is resolved: a still-overdue item remains visible. Existing save, return-to-close and return-to-queue choices remain available. No automatic notes, evidence links, status changes to other requests, messages or emails are created.
