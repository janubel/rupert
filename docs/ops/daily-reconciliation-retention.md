# Daily reconciliation and document retention

Open **Money → Daily reconciliation & documents** at `/daily_reconciliations`. This extends the daily register report with source controls, retained originals, source observations, report archives and review notes. All dates use Rupert's Eastern business timezone.

## Daily workflow

1. Pick a business day. Review recorded order totals, tax in the CSV/detailed register report, cash/card receipts, refunds, payment coverage issues and import freshness. An absent import is not a zero-sales day. Orders, tenders and refunds use their respective event dates.
2. Review SwipeSimple native transaction observations, Authorize.net API settlements, Authorize.net portal observations and NAB/IRIS snapshots separately. These may describe the same money; they are never summed into sales. API and portal evidence remain separate. IRIS windows may overlap and batch amounts do not establish net bank funding.
3. Retain the original daily report, invoice, bank statement, fee statement or screenshot. Supply its source and covered dates. Supported files: UTF-8 CSV/TXT/JSON, PDF, PNG and JPEG, up to 8 MiB. PDFs/images are retained as attachments; there is no automatic OCR or extraction. No vendor login is needed to retain a document.
4. To compare a source report, select **Register control**, a single day, explicit three-letter currency and the matching Rupert location. Blank location means the unassigned pool only, not all locations. Enter matching-definition order totals, cash/card receipts and positive refunds from the source. Amounts use currency units with at most two decimals. Missing fields stay blank/unknown. Tips, fees and deposits are retained as observations and remain unavailable for comparison when canonical fields do not exist. C-Trax has separate native day/control checks; Cash App evidence can be retained even when no canonical importer is available.
5. Read the variance as **Rupert minus source**. A matched recorded total means only that the specified totals agree. It does not certify completeness, fees, net settlement or bank receipt. Multiple active controls for the same pool are flagged as conflicting; do not add them together. To correct a control, choose **Correct this control** on its document card, attach its replacement and enter the new totals. Source, dates, currency and location must still match; both originals remain. Withdraw an accidental duplicate by choosing its current control and entering a reason to remove it from comparisons while retaining the original file, totals and explanation.
6. Keep a permanent report version and enter **Needs attention** or **Reviewed** notes. Reviewed records a human assessment and can include unresolved differences; it is not an automatic balance assertion. Reviews bind to a report fingerprint. A changed report is visibly flagged and stale form submissions are rejected. Reviews and documents are append-only through the application.

The existing **Daily / weekly / monthly source summary** is linked in both directions. Saving or refreshing that report, including its automatic closes, retains encrypted CSV and JSON versions in the same vault. The current summary can refresh while earlier versions remain downloadable.

## Differences and report follow-ups

The daily page starts with **What needs attention**: signed monetary differences, unavailable comparisons, conflicting controls and recorded activity without a current register control. Known differences appear first, grouped by currency and descending absolute difference within each currency. The direction is always **Rupert minus source**; amounts in different currencies are never summed. Filters show differences, unavailable values, conflicts, matched metrics or all metrics; the CSV remains complete.

Missing-control prompts come only from observed source/currency/location pools without a current control. **Add control** opens the original-file form with that exact day and scope. **Request report** creates a prefilled request. These prompts do not infer an exhaustive list of expected invoices or processor/bank reports. Use **Track another expected report** for those expectations, including monthly reports and statements.

**Money → Report requests & follow-ups** at `/reconciliation_follow_ups` keeps requests and difference investigations visible across dates. Choose an active report reader as owner, a due date and a concrete next step. The default queue shows open/waiting items earliest due first; filters include overdue, closed, source, owner and covered business day. Due dates use Rupert's Eastern date. These are local Rupert records, with no automatic messages or reminders.

Use **Record progress** to change status, assignment or due date, link matching vault evidence, add a progress/closing note or rename a follow-up. Each successful change keeps an encrypted history snapshot, including earlier titles, notes, assignments, evidence IDs and actor names. Source, document kind, period, currency/location and original purpose stay fixed; create a new request for a different scope. Optimistic locking rejects stale edits while preserving entered text for comparison with the latest history. Duplicate creation submissions reuse their saved request.

**Add original report** opens the attachment form with the requested context and returns to the follow-up after retention. Select its evidence and record progress to link it. Matching files must belong to the workspace, have the requested source/kind and cover the whole period; register controls also require the exact currency/location. The chooser shows the latest 100 matching vault files. Existing native CSVs still require manual coverage checks before retaining a covered vault original for linkage. Linking or uploading never closes a request automatically. **Closed by reviewer** records an explained decision, rather than certifying that a variance is fixed or a business day is complete. A changed report is flagged on a difference investigation.

Requests and history are tenant scoped and are not automatically pruned. Reading requires `reports.read`; creating/updating additionally requires `reports.write`. History snapshots are append-only through the application, and current-record changes and history writes commit together. They are included in the consistent database/configuration backup; keep Rails encryption keys for restoration. Follow-up status changes are separate from the financial report fingerprint and do not modify canonical transactions or source-control amounts.

## Across-day review

**Money → Reconciliation across days** at `/reconciliation_follow_ups/overview` shows seven Eastern business dates ending yesterday by default. Select an ending date, move a week or include today. Counts show missing register-control scopes, differences/unavailable/conflicting comparisons and open requests covering each day. Open the daily report for currency-separated amounts. Missing-control prompts reuse an existing open request with the exact source/day/currency/location when one exists. Closed requests do not remove a control gap. These are live local calculations; no provider fetch or automatic report request occurs.

Monthly requests appear on each covered date but remain one request. The next-follow-ups section includes the earliest due open/waiting items across all dates, including outside the visible week. No-control/no-request dates do not establish that all reports arrived, and this overview does not certify review completeness. Explicitly track other expected invoices and statements.

The overview puts the earliest due open follow-ups above the calendar and highlights overdue cards. **Register reports to request** lists observed control gaps without an existing open request, oldest date first, with the first three visible and the remainder in a keyboard-accessible disclosure. Search retained reports before creating a request. Each source/currency/location/date is a separate report scope. Creating an exact-scope open request removes its gap from this action list while the missing-control indicator remains until a control is supplied.

Follow-up cards offer **Record progress** directly at its form, **Find retained original** and **Add original** with preserved request context, or **Download linked original** once evidence is linked. Read-only users keep viewing/downloading actions. The daily attention section flags all-date overdue follow-ups; the document library offers overdue, due-today and unlinked-original shortcuts. These actions do not send report requests, close work or change evidence automatically.

Queue shortcuts show all-date counts for overdue, due today, unassigned and report requests without a linked original. Combine purpose, source, owner, evidence, status and covered-date filters for the list. Cards expose urgency, owner, latest progress note and whether evidence is linked; a retained file can exist without being linked to its request. The disconnected Drive page offers links back to this local workflow while consent remains pending.

## Automatic retention

`DailyReconciliationArchiveJob` runs at **07:15 America/New_York daily**. It revisits each of the previous seven calendar/business-report dates to capture late imports. Each changed report becomes a new encrypted CSV archive; unchanged snapshots replay to the existing archive. Days older than seven dates can be archived manually. The job reads local data and performs no provider operations or messaging.

C-Trax daily source pulls also retain versioned normalized JSON snapshots containing the already-filtered orders, sessions and controls. These are explicitly normalized source snapshots, not original native export bytes. Its store-day checks and cash-session drill-down are available on the daily page with the store timezone shown separately.

New native IRIS Daily Deposits and monthly Health CSV imports retain exact source bytes in the document vault in the same database transaction as parsed snapshots. Corrections preserve earlier bytes even though the existing parsed snapshot is replaced. A multi-month Health file is attached to each covered month. Replays are deduplicated by source, kind, period, original SHA-256 and metadata. Existing SwipeSimple and Authorize.net portal originals remain in their current encrypted tables and can be downloaded from the shared library with reports-read permission. The daily page shows the newest 20 native exports per source, with day-specific Authorize.net observations linking their original export even when older. **Money → Document retention library** at `/reconciliation_documents` searches across all retained dates by filename, source, reference, category and date range. Vault date filters intersect covered periods; native CSV filters use received export dates and do not claim transaction coverage. Pages contain up to 24 files, newest retained first, using tenant/filter-bound signed cursors. Browsing reads metadata without loading encrypted file bodies. Current controls, previous versions, withdrawal records and normalized snapshots have distinct labels; originals stay downloadable. Invalid upload/review/withdrawal forms preserve entered text and the selected day. A rejected upload requires selecting the file again.

Historical IRIS originals were not retained by previous importer versions and cannot be reconstructed from parsed snapshots. Reupload an available original or retain it directly. This workflow does not fabricate a native document from parsed data, certify API entitlement, or enable unavailable source integrations.

## Storage, access and recovery

Original file bytes are Base64 encoded then Rails-encrypted in `reconciliation_documents`, together with encrypted metadata. Downloads verify SHA-256 and byte size and use attachment disposition, no-store and nosniff headers. Filenames, source, period, checksums and retention timestamps are indexed metadata rather than secrets. Tenant scopes cover files, reviews and all report observations. Reading/exporting requires `reports.read`; uploading, archiving and reviewing additionally require `reports.write`. Existing source-import permissions continue to apply to imports.

There is **no automatic deletion** for documents, report archives or review notes, including when the nightly `DataRetention` service prunes derived mirrors/logs. This is an operational retention behavior, not a jurisdiction-specific legal retention period. There are no document deletion or replacement routes. Correct a document by adding a version. Protect administrative SQL/backup access separately; application callbacks are not protection against database administrators.

Evidence is stored inside Rupert's database and therefore included in consistent database backups. Preserve Rails encryption keys alongside backups in the established private backup process. The existing Google Drive database backup has a separate connection. [Automatic Drive document retention](drive-document-retention.md) adds a browsable folder of original files and report versions for this workspace after its administrator grants Google consent. Dropbox is not connected. Monitor database/backup size as source files accumulate. Keep off-host copies and test restoration and document decryption.

The archive CSV includes source-separated totals, coverage, freshness, controls/variances, native SwipeSimple totals/tips, gateway and portal observations, IRIS snapshot references, and retained document IDs/checksums/context. It is a reproducible report snapshot, not a bank ledger posting. No canonical sales, payments, inventory or external systems are changed by reconciliation.
