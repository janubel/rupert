# Expanding retained source history

Production source reads mirror into Rupert or retain encrypted evidence. Keep real exports, identifiers, account details, recovery keys and run receipts outside this public repository. A source's oldest returned record is evidence of available coverage, not proof of the business opening date or absence of older activity.

Before an operator backfill, take a consistent SQLite snapshot with the saved runtime encryption configuration, verify integrity and foreign keys, and preserve the current release. Use one active workspace at a time. Do not reset incremental watermarks or change the recurring schedule merely to read history.

## Source boundaries

- **Shopify:** check the app's granted access scopes before claiming older coverage. `CatalogSyncer` paginates its native orders query; pass an explicit historical lower date rather than the incremental watermark. Feed returned orders through `LedgerImporter.from_shopify_orders!`. Preserve older retained orders when the current grant exposes a shorter window. `read_all_orders` access requires the app's approved grant; a historical query cannot bypass that permission. See [Shopify access scopes](https://shopify.dev/docs/api/admin-graphql/2026-07/queries/currentAppInstallation).
- **Square orders:** `SquareClient.orders` reads completed orders with cursor pagination. Supply an explicit RFC 3339 lower bound and cover every location, including inactive locations, in batches of at most ten. Discover historical locations from the unfiltered `/locations` response: `SquareClient.locations` deliberately filters to active locations for routine catalog sync and therefore omits retired-store history. Reject a result reaching the client's cap as incomplete. Import through `LedgerImporter.from_square_orders!`; source IDs make overlap update the same canonical orders.
- **Square payment evidence:** read [ListPayments](https://developer.squareup.com/reference/square/payments-api/list-payments) for **each location explicitly**; an omitted location can select the default location. Set explicit beginning/end times because the default beginning is only one year ago. Follow every cursor, reject repeated cursors/IDs and retain all returned statuses. Read [ListPaymentRefunds](https://developer.squareup.com/reference/square/refunds-api/list-payment-refunds) separately with explicit times; without a location filter this endpoint covers the seller's locations. These source observations are reconciliation evidence, not additional canonical sales.
- **Square legacy transactions:** older payment history may remain in [ListTransactions](https://developer.squareup.com/reference/square/transactions-api/list-transactions). This deprecated read endpoint has no announced retirement date at the time of review. Cover each native location, including inactive locations, and follow every cursor. Preserve its native tenders/refunds separately; it can overlap modern payment and order records. Do not sum those pools or fabricate missing line items.
- **C-Trax:** start from the earliest store creation month exposed by the native store metadata. Enumerate completed order dates in bounded monthly reads using the existing store timezone and `completed_between` contract, validating every page. Run `Ctrax::SalesSync.call` for each returned historical business date. It retains daily order/register/control snapshots with native IDs and source digests. Dates with no returned orders are not claims of zero sales; do not infer that an empty month means there is no older history. Source snapshots stay separate from canonical sales. See [C-Trax retail](https://github.com/techmore/rupert/blob/6c744b5197929fd2111300d22fa9e4d75724eaee/docs/ctrax-retail.md).
- **SwipeSimple:** run the existing fresh-session `SwipesimpleWeb::Sync`. Its unfiltered export validates website row totals and supplies all history currently exposed below the vendor's 10,000-row limit. Retained original files and latest-identity reporting de-duplicate overlap. A new identical export updates verified-read time without storing another identical document. Larger history requires deliberately split vendor ranges. See [SwipeSimple reporting](swipesimple-reporting.md).
- **NAB / IRIS:** the automatic website pull covers the current and previous months. For older periods use the existing verified merchant identity, Daily Deposits read/export contract and `DailyDepositsCsvImport`, preserving each merchant/month separately. Native CSV rows and totals must match the source response before publication. The importer supports years 2000–2099. Verify empty source tables and zero totals explicitly; record their coverage privately instead of manufacturing transactions. Use bounded fresh sessions, preserve setup-version checks, and resume completed months after an interrupted run. See [IRIS reporting](https://github.com/techmore/rupert/blob/6c744b5197929fd2111300d22fa9e4d75724eaee/docs/ops/iris-reporting.md).
- **Authorize.net:** portal snapshots do not establish API reporting access. Run bounded API backfills only with an approved configured reporting connection; preserve portal originals where API access is absent. See [Authorize.net reporting](https://github.com/techmore/rupert/blob/6c744b5197929fd2111300d22fa9e4d75724eaee/docs/ops/authorize-net-reporting.md).

Retain native Square JSON evidence using `ReconciliationEvidence.retain!` with source `square`, kind `gateway_report`, native kind/location/environment and read-time metadata. Split by source month and bounded row batches below the evidence size limit. Keep refunds and payment statuses intact. These encrypted documents are supplemental evidence and must never be added to canonical sales totals.

## Verification and recovery

Canonical orders and retained original documents are not pruned by `DataRetention`. The derived `LedgerEntry` mirror has an existing 365-day window; use canonical orders and originals for long-term history rather than treating that mirror as a permanent archive.

Record counts and earliest/latest dates per source, the exact queried windows, pagination completion, permission/retention limits and failed windows. Compare stable account/role/login records and previously retained source IDs against the checkpoint. Repeating a canonical order import must not increase order counts or gross totals for identical input. Check original-document checksums through the application's decrypting accessors.

After the backfill, take another consistent database/configuration checkpoint. Restore it into an isolated database; run integrity and foreign-key checks, load the saved encryption configuration and read encrypted attributes. Do not restore over production as a test. Check the storage driver’s online snapshot behavior before creating an instance snapshot: a file-copy snapshot can freeze the running application. Use the online consistent database backup for recovery verification when availability is required. Encrypt the recovery archive before copying it off SER8, verify decryption and every member checksum, and use the existing owner-verified private backup destination.

The host's six-hour local timer and Google Drive backups are independent. Verify the actual timer result, matching database/environment/settings sidecars and a restore of the scheduled backup. A configured Drive OAuth client without a refresh token is not a connected backup. Consent and a verified upload/download remain required; see [Google backup verification](https://github.com/techmore/rupert/blob/6c744b5197929fd2111300d22fa9e4d75724eaee/docs/ops/google-backup-verification.md). Preserve the protected recovery key needed to decrypt off-host archives.

## QuickBooks history

Accounting history exported from QuickBooks is not a platform read and cannot be backfilled by a source sync. Upload it with **Bookkeeping → Records → QuickBooks import**: the original CSV is retained, parsed into staged rows, mapped to Rupert accounts by a person, and posted as journal entries only on approval (reversible by batch, never into a locked period). See [QuickBooks import](quickbooks-import.md) for the formats, assumptions that remain unverified, and the rules.
