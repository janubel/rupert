Deployment

Rupert is currently hosted at herbalhealers.rupertpos.com. The current production host is SER8 in an Incus instance.

Release and deployment

GitHub Actions runs CI; the Release workflow publishes a release from a version tag. SER8 has a separate host-side auto-deployer that polls main and installs only clean fast-forward commits with green CI (sqlite3), after taking a pre-deploy SQLite backup. A GitHub release itself does not deploy the live instance. See the SER8 deployment notes for the gates and manual mode.

Use the SER8-specific web, worker and backup units plus the host freshness watcher under deploy/. The pre-Incus droplet units were removed from the current tree on October 20, 2026; consult Git history only for historical context. Confirm active services before promotion.

Database

SQLite with FTS5 is the only supported database. Leave DATABASE_URL unset; configure the SQLite file with RUPERT_SQLITE_DATABASE_PRODUCTION. The October 13, 2026 cutover report records the original production migration. The live instance and release 11af6b8 were verified on October 14; see the deployment receipt. See SQLite and Incus operations for tuning, recovery and scaling decisions.

Optional Docker Compose

Compose runs a SQLite preflight and migrations before starting web/jobs. An existing deployment must supply a verified, nonempty SQLite database in the persistent rupert-storage volume at /app/storage/production.sqlite3. Only a brand new installation should set RUPERT_INITIALIZE_DATABASE=1 for its first start; unset it after initialization. Existing PostgreSQL data is not converted by Compose. Preserve old volumes and backups during any transition.

Backups

The cutover report records six-hourly local SQLite snapshots and settings/env backups. Verify off-host encrypted copies and a restore drill; local snapshots alone cannot recover from host loss.

Continuous integration

CI runs in the official ruby:4.0 container against SQLite, including RuboCop, migrations, Tailwind build, asset precompile, and the full test suite. Every push or pull request triggers it.
