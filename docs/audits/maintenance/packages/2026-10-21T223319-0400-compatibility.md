# Package and toolchain compatibility review

**Snapshot:** 2026-10-21 22:33 EDT
**Repository:** `techmore/rupert`; default/integration branch `main`
**Selected update:** employee mobile Expo SDK 58 compatibility, already tracked by [PR #300](https://github.com/techmore/rupert/pull/300).
**Scope:** version/support and advisory review of the Rails, Rust core, Shopify CLI, mobile, CI and container stacks. This is source and CI evidence, not deployment or operator acceptance.

## Findings

| Area | Locked/source state | Assessment and exposure |
| --- | --- | --- |
| Rails/Ruby | Main locks Rails 8.1.4 and Ruby 4.0.6; `.ruby-version`, `Gemfile.lock` and the application Dockerfile agree. Rails 8.1.4 is the latest 8.1 patch reviewed. Rails 8.1 remains in security support through 2027-10-10; its bug-fix window ended 2026-10-10. | The framework is current for security fixes. Ruby 4.0.7 has been available since 2026-09-15, while source/runtime pins remain 4.0.6. Ruby's 2026-08-27 advisory affects bundled `resolv` 0.7.0 and recommends 0.7.2 for CVE-2026-80212/80213. A source search found no direct `Resolv`/`resolv-replace` use; transitive/runtime reachability was not established. Update the runtime and lock together in the next dedicated security slice. Ruby and Bundler are absent on this host, so no Gem advisory scan or Rails tests were run here. |
| Rust core | Separate `rust-core` branch, edition 2024; lock includes axum 0.8.9 and rusqlite 0.40.2. CI installs current stable components but does not pin a minimum toolchain. | Not the production integration branch and must not be merged wholesale into `main`. A release receipt records Rust 1.99.1 binary `27fcd16` deployed to the separate SER8 `rupert-core` instance and scoped tests/parity. The branch tip also contains later backup/watch operations; no receipt establishes a rebuild of the latest branch tip. Public hostname/Caddy/DNS and webhook registration remain owner gates, so the separate service is not accepted as a Rails/POS replacement. No `cargo audit` scan was run. |
| Shopify CLI | Root lock resolves `@shopify/cli` 4.9.4; package range is `^4.9.4`. Root CI does not pin a Node version for this development CLI. The local Node 22.22.1 satisfies Shopify's documented Node >=22.12 requirement. | Development tooling only; this review performed no Shopify API/platform work. No CLI update was selected. The repository's owner-signoff rule still applies to every Shopify/Square data mutation. |
| Employee mobile | PR #300 aligns Expo to 58.0.17 and TypeScript to 6.0.3 while keeping React 19.3.0 and React Native 0.88.0; the lock removes the obsolete UUID override through `xcode` 4.0.0. | Expo's SDK 58 matrix specifies React 19.3.0, React Native 0.88 and Node >=22.13; the CI's Node 24 and local Node 22.22.1 meet that floor. Mobile source remains unsigned and undistributed; no physical-device or store acceptance is claimed. |
| CI/container | Rails CI uses floating `ruby:4.0`; app image is pinned to `ruby:4.0.6-alpine`. Mobile CI uses Node 24 on Ubuntu and exports with Hermes. Rust CI uses current stable on Ubuntu. | The Docker build is an independent shipped runtime pin and needs to move with the Ruby 4.0.7 follow-up. No architecture/image retag or CI/toolchain update was selected in this mobile batch. |

The Ruby advisory applies only when an application uses the affected `resolv` code path; the Ruby maintainers distinguish this from ordinary operating-system hostname resolution used by `Net::HTTP`. The source-only search is not enough to prove absence through dependencies, so treat the 4.0.6 runtime pin as an unresolved security follow-up rather than a confirmed exploitable path.
